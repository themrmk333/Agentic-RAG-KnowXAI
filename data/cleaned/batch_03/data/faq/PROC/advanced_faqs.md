# Procurement / Purchasing — Advanced FAQs (Edge Cases, Comparisons, Policy Interpretation)

## FAQADV-PROC-001: New Hardware/Equipment Request Procedure: What happens if Procurement Lead is unavailable to approve a purchase requisition?
**Category:** Edge Case / What-If | **Difficulty:** Advanced | **Access Level:** employee

**Answer:** Route it to the Procurement Lead's delegate (typically the next role up the escalation chain) via MK-ProcureX, tagged 'Delegate Approval Required'; the Procurement Lead is notified on return and can flag it for review within 5 business days if needed.

**Related Documents:** SOP-PROC-001-EDGE-A
---

## FAQADV-PROC-002: New Hardware/Equipment Request Procedure: Can a purchase requisition be expedited in a genuine emergency?
**Category:** Edge Case / What-If | **Difficulty:** Advanced | **Access Level:** employee

**Answer:** Yes, via the expedited path: get verbal pre-approval from the Procurement Lead directly, proceed with the minimum necessary action, then file the formal request in MK-ProcureX within 24 hours marked 'Emergency — Retroactive Approval'.

**Related Documents:** SOP-PROC-001-EDGE-B
---

## FAQADV-PROC-003: New Hardware/Equipment Request Procedure: What do I do if MK-ProcureX is down and I need to submit a purchase requisition?
**Category:** Edge Case / What-If | **Difficulty:** Advanced | **Access Level:** employee

**Answer:** Non-urgent requests should wait for MK-ProcureX to be restored. For genuinely urgent cases, email the Procurement Lead directly with the request details; once MK-ProcureX is back, enter the request and outcome retroactively, tagged 'Entered Retroactively — System Outage'.

**Related Documents:** SOP-PROC-001-EDGE-C
---

## FAQADV-PROC-004: New Hardware/Equipment Request Procedure: What happens if my purchase requisition request is rejected, or I accidentally submit it twice?
**Category:** Edge Case / What-If | **Difficulty:** Advanced | **Access Level:** employee

**Answer:** Rejections always come with a documented reason in MK-ProcureX — correct the issue and resubmit, or escalate once if you disagree. Duplicates are flagged automatically and reconciled by keeping the original and closing the duplicate with a cross-reference.

**Related Documents:** SOP-PROC-001-EDGE-D
---

## FAQADV-PROC-005: New Hardware/Equipment Request Procedure: What happens if my purchase requisition submission is missing required documentation?
**Category:** Edge Case / What-If | **Difficulty:** Advanced | **Access Level:** employee

**Answer:** The Procurement Lead returns the request in MK-ProcureX with a specific note on what's missing rather than approving or fixing it themselves; you have about 5 business days to correct and resubmit through the same request thread.

**Related Documents:** SOP-PROC-001-EDGE-E
---

## FAQADV-PROC-026: If I find an old reference to the Vendor Onboarding Policy that seems to disagree with what's current, which one is right?
**Category:** Policy Interpretation | **Difficulty:** Intermediate | **Access Level:** employee

**Answer:** The current version, POL-PROC-001, is always authoritative going forward. If an older cached or printed copy of the Vendor Onboarding Policy disagrees with it, treat the current document as correct and check the POL-PROC-001-HISTORY document to understand exactly what changed and when.

## FAQADV-PROC-028: What's the difference between the standard New Hardware/Equipment Request Procedure process and the emergency/expedited version?
**Category:** Comparison | **Difficulty:** Intermediate | **Access Level:** employee

**Answer:** The standard path (SOP-PROC-001) goes through Procurement Lead via MK-ProcureX in the normal order. The expedited path (SOP-PROC-001-EDGE-B) is only for genuine emergencies: it requires verbal pre-approval first, immediate action, then retroactive formal filing within 24 hours — and repeated use of the expedited path for the same request type triggers a review.

**Related Documents:** SOP-PROC-001, SOP-PROC-001-EDGE-B
