# QA / Testing — Advanced FAQs (Edge Cases, Comparisons, Policy Interpretation)

## FAQADV-QA-001: Software Defect Reporting Procedure: What happens if QA Lead is unavailable to approve a defect report?
**Category:** Edge Case / What-If | **Difficulty:** Advanced | **Access Level:** employee

**Answer:** Route it to the QA Lead's delegate (typically the next role up the escalation chain) via MK-TestHub, tagged 'Delegate Approval Required'; the QA Lead is notified on return and can flag it for review within 5 business days if needed.

**Related Documents:** SOP-QA-001-EDGE-A
---

## FAQADV-QA-002: Software Defect Reporting Procedure: Can a defect report be expedited in a genuine emergency?
**Category:** Edge Case / What-If | **Difficulty:** Advanced | **Access Level:** employee

**Answer:** Yes, via the expedited path: get verbal pre-approval from the QA Lead directly, proceed with the minimum necessary action, then file the formal request in MK-TestHub within 24 hours marked 'Emergency — Retroactive Approval'.

**Related Documents:** SOP-QA-001-EDGE-B
---

## FAQADV-QA-003: Software Defect Reporting Procedure: What do I do if MK-TestHub is down and I need to submit a defect report?
**Category:** Edge Case / What-If | **Difficulty:** Advanced | **Access Level:** employee

**Answer:** Non-urgent requests should wait for MK-TestHub to be restored. For genuinely urgent cases, email the QA Lead directly with the request details; once MK-TestHub is back, enter the request and outcome retroactively, tagged 'Entered Retroactively — System Outage'.

**Related Documents:** SOP-QA-001-EDGE-C
---

## FAQADV-QA-004: Software Defect Reporting Procedure: What happens if my defect report request is rejected, or I accidentally submit it twice?
**Category:** Edge Case / What-If | **Difficulty:** Advanced | **Access Level:** employee

**Answer:** Rejections always come with a documented reason in MK-TestHub — correct the issue and resubmit, or escalate once if you disagree. Duplicates are flagged automatically and reconciled by keeping the original and closing the duplicate with a cross-reference.

**Related Documents:** SOP-QA-001-EDGE-D
---

## FAQADV-QA-005: Software Defect Reporting Procedure: What happens if my defect report submission is missing required documentation?
**Category:** Edge Case / What-If | **Difficulty:** Advanced | **Access Level:** employee

**Answer:** The QA Lead returns the request in MK-TestHub with a specific note on what's missing rather than approving or fixing it themselves; you have about 5 business days to correct and resubmit through the same request thread.

**Related Documents:** SOP-QA-001-EDGE-E
---

## FAQADV-QA-027: What's the difference between the standard Software Defect Reporting Procedure process and the emergency/expedited version?
**Category:** Comparison | **Difficulty:** Intermediate | **Access Level:** employee

**Answer:** The standard path (SOP-QA-001) goes through QA Lead via MK-TestHub in the normal order. The expedited path (SOP-QA-001-EDGE-B) is only for genuine emergencies: it requires verbal pre-approval first, immediate action, then retroactive formal filing within 24 hours — and repeated use of the expedited path for the same request type triggers a review.

**Related Documents:** SOP-QA-001, SOP-QA-001-EDGE-B
