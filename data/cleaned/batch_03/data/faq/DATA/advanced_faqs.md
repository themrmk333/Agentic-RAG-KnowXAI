# Data & Analytics — Advanced FAQs (Edge Cases, Comparisons, Policy Interpretation)

## FAQADV-DATA-001: Data Access Request Procedure: What happens if Data Manager is unavailable to approve a data access request?
**Category:** Edge Case / What-If | **Difficulty:** Advanced | **Access Level:** employee

**Answer:** Route it to the Data Manager's delegate (typically the next role up the escalation chain) via MK-DataLake, tagged 'Delegate Approval Required'; the Data Manager is notified on return and can flag it for review within 5 business days if needed.

**Related Documents:** SOP-DATA-001-EDGE-A
---

## FAQADV-DATA-002: Data Access Request Procedure: Can a data access request be expedited in a genuine emergency?
**Category:** Edge Case / What-If | **Difficulty:** Advanced | **Access Level:** employee

**Answer:** Yes, via the expedited path: get verbal pre-approval from the Data Manager directly, proceed with the minimum necessary action, then file the formal request in MK-DataLake within 24 hours marked 'Emergency — Retroactive Approval'.

**Related Documents:** SOP-DATA-001-EDGE-B
---

## FAQADV-DATA-003: Data Access Request Procedure: What do I do if MK-DataLake is down and I need to submit a data access request?
**Category:** Edge Case / What-If | **Difficulty:** Advanced | **Access Level:** employee

**Answer:** Non-urgent requests should wait for MK-DataLake to be restored. For genuinely urgent cases, email the Data Manager directly with the request details; once MK-DataLake is back, enter the request and outcome retroactively, tagged 'Entered Retroactively — System Outage'.

**Related Documents:** SOP-DATA-001-EDGE-C
---

## FAQADV-DATA-004: Data Access Request Procedure: What happens if my data access request request is rejected, or I accidentally submit it twice?
**Category:** Edge Case / What-If | **Difficulty:** Advanced | **Access Level:** employee

**Answer:** Rejections always come with a documented reason in MK-DataLake — correct the issue and resubmit, or escalate once if you disagree. Duplicates are flagged automatically and reconciled by keeping the original and closing the duplicate with a cross-reference.

**Related Documents:** SOP-DATA-001-EDGE-D
---

## FAQADV-DATA-005: Data Access Request Procedure: What happens if my data access request submission is missing required documentation?
**Category:** Edge Case / What-If | **Difficulty:** Advanced | **Access Level:** employee

**Answer:** The Data Manager returns the request in MK-DataLake with a specific note on what's missing rather than approving or fixing it themselves; you have about 5 business days to correct and resubmit through the same request thread.

**Related Documents:** SOP-DATA-001-EDGE-E
---

## FAQADV-DATA-026: If I find an old reference to the Data Governance Policy that seems to disagree with what's current, which one is right?
**Category:** Policy Interpretation | **Difficulty:** Intermediate | **Access Level:** employee

**Answer:** The current version, POL-DATA-001, is always authoritative going forward. If an older cached or printed copy of the Data Governance Policy disagrees with it, treat the current document as correct and check the POL-DATA-001-HISTORY document to understand exactly what changed and when.

**Related Documents:** POL-DATA-001, POL-DATA-001-HISTORY
---

## FAQADV-DATA-027: What's the difference between the standard Data Access Request Procedure process and the emergency/expedited version?
**Category:** Comparison | **Difficulty:** Intermediate | **Access Level:** employee

**Answer:** The standard path (SOP-DATA-001) goes through Data Manager via MK-DataLake in the normal order. The expedited path (SOP-DATA-001-EDGE-B) is only for genuine emergencies: it requires verbal pre-approval first, immediate action, then retroactive formal filing within 24 hours — and repeated use of the expedited path for the same request type triggers a review.

**Related Documents:** SOP-DATA-001, SOP-DATA-001-EDGE-B
---
