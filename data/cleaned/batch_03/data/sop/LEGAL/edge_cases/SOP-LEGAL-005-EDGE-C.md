## Situation
MK-LegalVault is down, in scheduled maintenance, or otherwise unreachable, but the ip filing request genuinely cannot wait until the system is restored.

## Detection
requester attempts to log into MK-LegalVault and receives a system-unavailable error, or has received a maintenance notification covering the relevant window (see the Communications archive).

## Decision Criteria
requester first checks whether the request is time-sensitive enough to justify an off-system workaround, or whether it can simply wait for MK-LegalVault to be restored (the default expectation).

## Steps

1. requester confirms MK-LegalVault is genuinely unavailable (not just a personal connectivity issue) by checking with a colleague or the IT status page.
2. For non-urgent ip filing request requests, requester waits for MK-LegalVault to be restored and submits normally — this is the default and preferred path.
3. For genuinely urgent requests, requester documents the request details (who, what, why, when) in an email to the General Counsel instead of the system.
4. The General Counsel reviews the emailed request using the same criteria they would apply inside MK-LegalVault, and replies with an approval/rejection decision in writing.
5. Once MK-LegalVault is restored, requester or the General Counsel re-enters the request and its outcome into MK-LegalVault retroactively, referencing the original email for the audit trail.
6. MK-LegalVault's record is tagged 'Entered Retroactively — System Outage' so reporting doesn't mistake the entry date for the actual request date.

requester

## Escalation
Legal Associate -> Contracts Specialist -> Legal Manager -> General Counsel

## Expected Result
The ip filing request is actioned without waiting for system restoration when genuinely urgent, while still ending up fully and correctly recorded in MK-LegalVault once it's back online.
