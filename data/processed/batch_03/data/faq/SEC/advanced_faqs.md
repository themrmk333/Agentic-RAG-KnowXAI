# Cybersecurity / Information Security — Advanced FAQs (Edge Cases, Comparisons, Policy Interpretation)

## FAQADV-SEC-001: Phishing Email Reporting Procedure: What happens if Security Analyst is unavailable to approve a phishing report?
**Category:** Edge Case / What-If | **Difficulty:** Advanced | **Access Level:** employee

**Answer:** Route it to the Security Analyst's delegate (typically the next role up the escalation chain) via MK-SecGuard, tagged 'Delegate Approval Required'; the Security Analyst is notified on return and can flag it for review within 5 business days if needed.

**Related Documents:** SOP-SEC-001-EDGE-A
---

## FAQADV-SEC-002: Phishing Email Reporting Procedure: Can a phishing report be expedited in a genuine emergency?
**Category:** Edge Case / What-If | **Difficulty:** Advanced | **Access Level:** employee

**Answer:** Yes, via the expedited path: get verbal pre-approval from the Security Analyst directly, proceed with the minimum necessary action, then file the formal request in MK-SecGuard within 24 hours marked 'Emergency — Retroactive Approval'.

**Related Documents:** SOP-SEC-001-EDGE-B
---

## FAQADV-SEC-003: Phishing Email Reporting Procedure: What do I do if MK-SecGuard is down and I need to submit a phishing report?
**Category:** Edge Case / What-If | **Difficulty:** Advanced | **Access Level:** employee

**Answer:** Non-urgent requests should wait for MK-SecGuard to be restored. For genuinely urgent cases, email the Security Analyst directly with the request details; once MK-SecGuard is back, enter the request and outcome retroactively, tagged 'Entered Retroactively — System Outage'.

**Related Documents:** SOP-SEC-001-EDGE-C
---

## FAQADV-SEC-004: Phishing Email Reporting Procedure: What happens if my phishing report request is rejected, or I accidentally submit it twice?
**Category:** Edge Case / What-If | **Difficulty:** Advanced | **Access Level:** employee

**Answer:** Rejections always come with a documented reason in MK-SecGuard — correct the issue and resubmit, or escalate once if you disagree. Duplicates are flagged automatically and reconciled by keeping the original and closing the duplicate with a cross-reference.

**Related Documents:** SOP-SEC-001-EDGE-D
---

## FAQADV-SEC-005: Phishing Email Reporting Procedure: What happens if my phishing report submission is missing required documentation?
**Category:** Edge Case / What-If | **Difficulty:** Advanced | **Access Level:** employee

**Answer:** The Security Analyst returns the request in MK-SecGuard with a specific note on what's missing rather than approving or fixing it themselves; you have about 5 business days to correct and resubmit through the same request thread.

**Related Documents:** SOP-SEC-001-EDGE-E

## FAQADV-SEC-031: What's the difference between the standard Phishing Email Reporting Procedure process and the emergency/expedited version?
**Category:** Comparison | **Difficulty:** Intermediate | **Access Level:** employee

**Answer:** The standard path (SOP-SEC-001) goes through Security Analyst via MK-SecGuard in the normal order. The expedited path (SOP-SEC-001-EDGE-B) is only for genuine emergencies: it requires verbal pre-approval first, immediate action, then retroactive formal filing within 24 hours — and repeated use of the expedited path for the same request type triggers a review.

**Related Documents:** SOP-SEC-001, SOP-SEC-001-EDGE-B
