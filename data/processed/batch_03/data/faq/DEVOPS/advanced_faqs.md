# DevOps & Cloud — Advanced FAQs (Edge Cases, Comparisons, Policy Interpretation)

## FAQADV-DEVOPS-001: Service Deployment Procedure: What happens if DevOps Manager is unavailable to approve a deployment?
**Category:** Edge Case / What-If | **Difficulty:** Advanced | **Access Level:** employee

**Answer:** Route it to the DevOps Manager's delegate (typically the next role up the escalation chain) via MK-CloudOps, tagged 'Delegate Approval Required'; the DevOps Manager is notified on return and can flag it for review within 5 business days if needed.

**Related Documents:** SOP-DEVOPS-001-EDGE-A
---

## FAQADV-DEVOPS-002: Service Deployment Procedure: Can a deployment be expedited in a genuine emergency?
**Category:** Edge Case / What-If | **Difficulty:** Advanced | **Access Level:** employee

**Answer:** Yes, via the expedited path: get verbal pre-approval from the DevOps Manager directly, proceed with the minimum necessary action, then file the formal request in MK-CloudOps within 24 hours marked 'Emergency — Retroactive Approval'.

**Related Documents:** SOP-DEVOPS-001-EDGE-B
---

## FAQADV-DEVOPS-003: Service Deployment Procedure: What do I do if MK-CloudOps is down and I need to submit a deployment?
**Category:** Edge Case / What-If | **Difficulty:** Advanced | **Access Level:** employee

**Answer:** Non-urgent requests should wait for MK-CloudOps to be restored. For genuinely urgent cases, email the DevOps Manager directly with the request details; once MK-CloudOps is back, enter the request and outcome retroactively, tagged 'Entered Retroactively — System Outage'.

**Related Documents:** SOP-DEVOPS-001-EDGE-C
---

## FAQADV-DEVOPS-004: Service Deployment Procedure: What happens if my deployment request is rejected, or I accidentally submit it twice?
**Category:** Edge Case / What-If | **Difficulty:** Advanced | **Access Level:** employee

**Answer:** Rejections always come with a documented reason in MK-CloudOps — correct the issue and resubmit, or escalate once if you disagree. Duplicates are flagged automatically and reconciled by keeping the original and closing the duplicate with a cross-reference.

**Related Documents:** SOP-DEVOPS-001-EDGE-D
---

## FAQADV-DEVOPS-005: Service Deployment Procedure: What happens if my deployment submission is missing required documentation?
**Category:** Edge Case / What-If | **Difficulty:** Advanced | **Access Level:** employee

**Answer:** The DevOps Manager returns the request in MK-CloudOps with a specific note on what's missing rather than approving or fixing it themselves; you have about 5 business days to correct and resubmit through the same request thread.

**Related Documents:** SOP-DEVOPS-001-EDGE-E
---

## FAQADV-DEVOPS-026: If I find an old reference to the Production Change Policy that seems to disagree with what's current, which one is right?
**Category:** Policy Interpretation | **Difficulty:** Intermediate | **Access Level:** employee

**Answer:** The current version, POL-DEVOPS-001, is always authoritative going forward. If an older cached or printed copy of the Production Change Policy disagrees with it, treat the current document as correct and check the POL-DEVOPS-001-HISTORY document to understand exactly what changed and when.

**Related Documents:** POL-DEVOPS-001, POL-DEVOPS-001-HISTORY
---

## FAQADV-DEVOPS-027: What's the difference between the standard Service Deployment Procedure process and the emergency/expedited version?
**Category:** Comparison | **Difficulty:** Intermediate | **Access Level:** employee

**Answer:** The standard path (SOP-DEVOPS-001) goes through DevOps Manager via MK-CloudOps in the normal order. The expedited path (SOP-DEVOPS-001-EDGE-B) is only for genuine emergencies: it requires verbal pre-approval first, immediate action, then retroactive formal filing within 24 hours — and repeated use of the expedited path for the same request type triggers a review.

**Related Documents:** SOP-DEVOPS-001, SOP-DEVOPS-001-EDGE-B
---
