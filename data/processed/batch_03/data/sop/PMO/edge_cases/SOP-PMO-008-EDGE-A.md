## Scenario
The designated approver (Program Manager) is on leave, travel, or otherwise unreachable within the normal response window, but the milestone acceptance cannot wait for their return.

## Deviation Procedure

1. Project Manager confirms the Program Manager has an active out-of-office status in MK-PMTrack or MK-HRMS before invoking this path.
2. Project Manager identifies the Program Manager's designated delegate — typically the next role up the escalation chain (Project Coordinator -> Project Manager -> PMO Lead -> PMO Director) — as recorded in MK-PMTrack.
3. Project Manager resubmits or flags the existing request in MK-PMTrack, tagging it 'Delegate Approval Required' with the reason.
4. The delegate reviews the request using the same criteria the original Program Manager would apply, and either approves, rejects, or requests clarification.
5. Once the Program Manager returns, they are notified of the delegate decision for their records; they may flag it for a follow-up review within 5 business days if something looks inconsistent with policy.
6. MK-PMTrack logs both the delegate's identity and the reason for delegation on the request record for audit purposes.

## Important Note
Delegation does not apply to Milestone Sign-off Procedure decisions explicitly reserved for the Program Manager by policy (e.g., anything requiring named signing authority); those must wait for the Program Manager's return or be routed to the next level up, not a lateral delegate.

## Escalation
If this edge case procedure itself cannot be completed, escalate through: Project Coordinator -> Project Manager -> PMO Lead -> PMO Director.
