## Procedure

**Step 1:** the Project Coordinator confirms the exact symptom, when it started, and whether it affects one system or several.

**Step 2:** the Project Coordinator performs the standard first-line check: identifying which upstream system or team Project Management / PMO depends on for the affected process.

**Step 3:** If the issue persists, the Project Coordinator applies the documented workaround for this issue type.

**Step 4:** the Project Coordinator checks whether the issue is isolated to their own account/device or is affecting other users too.

**Step 5:** If still unresolved, the Project Coordinator raises a ticket in MK-PMTrack categorised under 'Dependency Failure', attaching screenshots or error logs.

**Step 6:** The assigned specialist reproduces the issue, diagnoses the root cause, and applies a fix or a temporary workaround.

**Step 7:** the Project Coordinator confirms the fix works; the ticket is closed in MK-PMTrack with the root cause logged. If the dependency is another department, Project Management / PMO notifies that department's escalation contact directly rather than waiting silently.
