## Purpose

This advanced procedure defines how Software Engineering / Development handles **software engineering / development dependency failure recovery procedure**, covering a scenario beyond the department's routine day-to-day operations.

## Scope

Applies to Software Engineer and Engineering Manager within Software Engineering / Development.

## Procedure

**Step 1:** the Software Engineer confirms the exact symptom, when it started, and whether it affects one system or several.

**Step 2:** the Software Engineer performs the standard first-line check: identifying which upstream system or team Software Engineering / Development depends on for the affected process.

**Step 3:** If the issue persists, the Software Engineer applies the documented workaround for this issue type.

**Step 4:** the Software Engineer checks whether the issue is isolated to their own account/device or is affecting other users too.

**Step 5:** If still unresolved, the Software Engineer raises a ticket in MK-CodeForge categorised under 'Dependency Failure', attaching screenshots or error logs.

**Step 6:** The assigned specialist reproduces the issue, diagnoses the root cause, and applies a fix or a temporary workaround.

**Step 7:** the Software Engineer confirms the fix works; the ticket is closed in MK-CodeForge with the root cause logged. If the dependency is another department, Software Engineering / Development notifies that department's escalation contact directly rather than waiting silently.

## Exceptions
