## Scenario
The designated approver (Network Administrator) is on leave, travel, or otherwise unreachable within the normal response window, but the network connectivity cannot wait for their return.

## Deviation Procedure

1. employee confirms the Network Administrator has an active out-of-office status in MK-ServiceDesk or MK-HRMS before invoking this path.
2. employee identifies the Network Administrator's designated delegate — typically the next role up the escalation chain (IT Support Engineer -> IT Manager -> IT Director) — as recorded in MK-ServiceDesk.
3. employee resubmits or flags the existing request in MK-ServiceDesk, tagging it 'Delegate Approval Required' with the reason.
4. The delegate reviews the request using the same criteria the original Network Administrator would apply, and either approves, rejects, or requests clarification.
5. Once the Network Administrator returns, they are notified of the delegate decision for their records; they may flag it for a follow-up review within 5 business days if something looks inconsistent with policy.
6. MK-ServiceDesk logs both the delegate's identity and the reason for delegation on the request record for audit purposes.

## Important Note
Delegation does not apply to Corporate Wi-Fi Troubleshooting Escalation decisions explicitly reserved for the Network Administrator by policy (e.g., anything requiring named signing authority); those must wait for the Network Administrator's return or be routed to the next level up, not a lateral delegate.

## Escalation
If this edge case procedure itself cannot be completed, escalate through: IT Support Engineer -> IT Manager -> IT Director.
